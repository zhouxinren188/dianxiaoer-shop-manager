# 淘宝搜同款当前诊断摘要

更新时间：2026-08-12 04:04（Asia/Shanghai）

## 目标与安全边界

- 搜索固定使用专用持久分区：`persist:dianxiaoer-taobao-same-search-v1`。
- 专用搜索账号从登录开始就在最终搜索分区中完成登录，搜索窗口长期复用。
- 搜索绝不读取、复制、注入或清理 `persist:purchase-*` 的 Cookie 或站点存储。
- 搜索结果打开后的商品页、SKU、价格、改地址和下单仍使用当前采购账号分区：`persist:purchase-{accountId}`。

## 已排除的问题

1. 登录前没有提前发送 MTOP。首次点击只打开专用账号登录窗口并返回 `needLogin`；图片准备和 `request attempt=1` 均发生在用户登录完成、再次点击搜索之后。
2. 请求参数主体与蚂蚁工具箱成功样本一致：API、版本、`appId=34850`、`appKey=12574478`、`jsv=2.7.4`、`ttid`、签名算法和页面内 `XMLHttpRequest` 发送方式一致。
3. `bx-ua`、`bx-umidtoken`、`bx_et` 缺失不是已证实根因。蚂蚁工具箱已知成功样本三项同样全部缺失，第一次 MTOP 仍成功返回原始 60 条。
4. 当前页面确实是预期承载页：初始地址会自然落到 `https://h5.m.taobao.com/detailplugin/expired.html`。

## 当前仍未解决的问题

店小二当前请求在登录 Cookie、Token、承载页和页面内 XHR 均存在的情况下，仍快速返回无验证 URL 的 `RGV587`。现有证据不能把它归因于 Bixi、固定接口参数或真正的服务繁忙。

下一步应由成功案例环境逐项对照，且一次只验证一个变量：

1. 成功工具与店小二实际 BrowserWindow/partition 创建、登录回跳及承载页复用源码差异。
2. 登录完成后 Cookie、Token、导航与页面稳定算法的精确时序差异。
3. 首次搜索前是否有额外的页面资源、Service Worker、IndexedDB 或缓存生命周期差异。
4. 成功请求的脱敏真实出站请求头名称、Origin/Referer/UA/Client Hints 与店小二 CDP 记录的差异。
5. Chrome 134 与 Chrome 146 的网络栈或淘宝风控识别差异；不要伪装 UA 后下结论，因为 TLS/Client Hints 仍来自实际 Chromium。

## 当前代码行为

- `RGV587` 带验证 URL：在同一个专用搜索窗口打开验证地址，等待用户完成。
- `RGV587` 无验证 URL：最多进行一次受控重试；该决策不依赖 Bixi 是否存在。
- Token 错误：只有同一分区读到不同的新 Token 时才重试。
- 不刷新循环、不清理会话、不重建 partition、不复制采购 Cookie。
