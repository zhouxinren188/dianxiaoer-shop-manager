## 成功环境的关键特征

1. 淘宝账号从登录开始就在最终持久 partition 中完成正常登录。
2. 登录窗口与搜索窗口使用完全相同的 partition。
3. partition 长期保留 Cookie、LocalStorage、IndexedDB、Service Worker、缓存和设备状态。
4. 同一个搜索 BrowserWindow 按 partition 长期复用；承载页只在窗口首次创建时加载一次。
5. 承载页：`https://h5.m.taobao.com/awp/core/detail.htm?id=620000000000000000`，实际会落到 `detailplugin/expired.html`。
6. 请求由该淘宝页面内部的原生 `XMLHttpRequest` 发出，`withCredentials=true`。
7. 只显式设置 `Content-Type`；Cookie、Origin、Referer、User-Agent 和 Chromium 网络上下文均由同一个页面自然产生。
8. 发送前等待登录页/自动登录流程结束、导航稳定、登录 Cookie 存在以及 `_m_h5_tk` 稳定。
9. 普通 SUCCESS、RGV587、Token 刷新不会清理整个持久会话，也不会每次重建窗口。

## RGV587 的正确理解

蚂蚁工具箱历史日志中也出现过 RGV587：当时会话尚未完整稳定，淘宝返回登录地址；在同一个 partition 中完成流程后，即使仍没有 Bixi 三项，下一次请求也直接成功。

所以 RGV587 不能简单解释成：

- 接口真的繁忙；或
- 缺少 Bixi；或
- 参数固定错误。

需要结合是否返回验证 URL、登录流程、页面/Token 稳定性和完整网络环境判断。没有验证 URL 时也不应高频刷新或无限重试。
