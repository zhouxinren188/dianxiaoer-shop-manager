# 退货包裹反查采购单方案

记录日期：2026-08-30

更新日期：2026-08-31

状态：服务端接口与匹配器已完成本地实现与整体验证，待提交和服务端部署

## 目标

仓库收到消费者退货包裹后，通过退货物流单号直接查出对应的店小二采购单，帮助用户找到原采购平台订单并申请供应商退款。

## 已实现接口

GET /api/purchase-orders/by-return-logistics/:logisticsNo

接口会先按当前用户可访问的店铺查询 sales_return_logistics，再查找对应销售单和采购单。主账号按 owner_id 隔离，子账号同时受店铺权限和采购账号分配权限限制。

## 关联链路

1. 京东售后服务单同步保存退货物流单号、售后服务单号、销售订单号和京东 SKU。
2. 店小二采购单保存关联销售订单号和京东销售 SKU。
3. 优先使用“销售订单号 + 京东 SKU”精确匹配采购单。
4. 用户输入或扫描退货物流单号后，接口按退货商品分别返回采购单匹配结果。

## 匹配规则

1. 一个退货 SKU 只匹配到一个有效采购单时，match_mode 为 exact，不要求人工核对。
2. 同一销售订单、同一京东 SKU 存在多个有效采购单时，全部返回，match_mode 为 exact_multiple，并提示人工核对。
3. 售后数据没有 SKU 或无法精确匹配时，降级返回该销售订单下全部有效采购单，match_mode 为 sales_order_fallback，并提示人工核对。
4. pending、cancelled、failed、purchase_failed、unpaid 等未付款、已取消或采购失败记录不会作为有效退款目标。
5. 同一物流单号包含多个 SKU 时按 SKU 分组返回，重复售后记录会合并售后服务单号，不会错误合并不同商品。
6. 没有有效候选时返回 not_found，不静默指向错误采购单。

## 返回摘要

- logistics_no：查询的退货物流单号
- packages：按销售订单与京东 SKU 分组的退货商品及匹配采购单
- package_count：退货商品分组数
- matched_purchase_count：匹配到的采购单数
- needs_manual_review：是否需要人工核对

## 隐私与权限

- 查询使用参数化 SQL，并限制 owner_id 和可访问店铺。
- 子账号继续按 user_purchase_accounts 过滤采购账号。
- 接口不查询、不返回客户姓名、电话、地址等敏感字段。

## 自动化覆盖

- 唯一精确匹配、多采购单、缺少 SKU 降级、多 SKU 同包裹、重复记录合并、无有效候选。
- 路由顺序、店铺权限、子账号采购账号权限、参数化查询和隐私字段契约。
